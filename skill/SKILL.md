# Moodle МИСИС — рабочий навык (обновлён 23.10.2026)

## 0. Цель и базовое правило

Когда пользователь пишет «мудл», «ВВС», «лекция», «задания МИСИС», «newlms» или явно говорит о Moodle МИСИС, работать с **его личным Moodle** `https://newlms.misis.ru`, а не подменять запрос публичным поиском. Сначала пытаться решить задачу через уже авторизованный клиент на Windows; веб-браузер — запасной маршрут для функций, недоступных через API, либо для визуального изучения презентаций. Не просить у пользователя пароль или ручную работу, пока не проверено доступное подключение.

**Искомый результат важнее формального вызова API.** Для вопроса «найди презентацию» недостаточно вывести ссылку на урок: нужно разобрать его содержимое, найти `iframe`, проверить URL презентации; если пользователь просит прочитать слайды — попытаться получить и проверить именно их текст/изображения. Для задания — смотреть формулировку, вложения, рубрику, состояние отправки и комментарии, а не только название. Не выдавать имя файла/ссылку за фактически прочитанное содержимое.

## 1. Подключение: где, как и что нельзя трогать

- Windows: действующий авторизованный пользователь; старое имя устройства `WIN-2LK6007IEBP` **не является постоянным ID**.
- Приоритет инструментов: подключённый `Remote_Desktop_Commander` (`list_devices` → актуальное online-устройство → `start_process`) или `Windows_Bridge` (`device_status`, `bridge_capabilities`, разрешённые операции). Возможности и ограничения конкретного соединения выяснять заново. Если инструмент не найден среди видимых — искать его в каталоге `ALL_TOOLS` через `functions.exec`.
- Локальная папка: `C:\Users\user\Documents\MISIS-Moodle-Bridge`.
- Клиент: `moodle_client.py`; интерпретатор: `C:\Users\user\AppData\Local\Programs\Python\Python313\python.exe`.
- Авторизация хранится **только на компьютере** в `.moodle_credentials.dpapi` (Windows DPAPI, привязка к учётной записи). Не читать, не печатать, не копировать, не экспортировать файл, пароль, токен, `site_info` целиком, `userprivateaccesskey`, параметры авторизованных URL и тела POST. Не включать секреты в скрипты/логи/репозитории. Не отправлять токен в внешние Google/другие домены.
- Основной локальный навык агента: `C:\Users\user\.codex\skills\misis-moodle\SKILL.md`; резервная копия: `C:\Users\user\Documents\MISIS-Moodle-Bridge\skill\SKILL.md`; библиотечная версия: `/Moodle MISIS/SKILL.md`. Рецепты в соседнем `API_RECIPES.md`. При расхождениях использовать более свежие подтверждённые сведения, **не перезаписывать другую версию без проверки**.

**Начальная команда** (на удалённой Windows, а НЕ в облачном контейнере ChatGPT):

```powershell
& 'C:\Users\user\AppData\Local\Programs\Python\Python313\python.exe' 'C:\Users\user\Documents\MISIS-Moodle-Bridge\moodle_client.py' check
```

`check` возвращает `ok`, количества доступных курсов/заданий и предупреждения. Дополнительные команды: `courses`, `tasks`, `full` (создаёт свежий локальный `moodle_report.json`), `selftest`. `setup` требует ручного ввода учётных данных; `logout` удаляет секрет: **не вызывать без прямой просьбы**. Скрипты с именами `verify_*`, `submit_*`, `repair_*` могут делать реальные изменения: читать их до запуска, не запускать ради диагностики по названию.

Если `check` неуспешен: проверить состояние соединения, доступность ПК, путь/Python/клиент и только затем ошибку DPAPI/авторизации. В новом чате также открыть `/Moodle MISIS/MISIS_MOODLE_CONNECTION_HANDOFF.md`. Отсутствие ответа от агента ≠ отказ Moodle. Не обещать автономный API из облака при выключенном ПК.

## 2. Безопасные вызовы API — пример и формат параметров

Запускай временные **локальные** скрипты, выводящие только нужные данные; при смене Windows-пользователя учётные данные DPAPI могут оказаться недоступными.

```python
import moodle_client as m

token, site = m.site_info(m.read_credential())  # НИКОГДА не печатать оба объекта
course_id = 3417                         # пример, сначала определять актуальный ID
sections = m.call(token, 'core_course_get_contents', {'courseid': course_id})
for sec in sections:
    print(sec.get('name'))
    for item in sec.get('modules', []):
        print(item.get('name'), item.get('modname'), item.get('id'), item.get('url'))
```

**Существенная тонкость:** у этого клиента `m.call` формирует обычные POST-поля, **не разворачивает Python-списки в массивы Moodle**. Не писать `{'courseids':[3417]}`: получалась ошибка `invalidparameter`. Корректно: `{'courseids[0]': 3417}`. Для множества: `{'courseids[0]': 3417, 'courseids[1]': 3637}`. Аналогично для прочих структурных параметров API. `invalidparameter` — сначала проверить параметры, типы и индексацию, а не объявлять отсутствие прав.

Проверяй `warnings` и фактические права; пустой список не обязательно означает отсутствие материала (возможно, другой тип модуля или неполная выдача). Не выводи всё `site_info`: кроме имени пользователя там встречаются чувствительные поля.

## 3. Маршрутизация задач

| Запрос | Метод/действие (по умолчанию чтение) |
|---|---|
| «мудл», ближайшие дедлайны | `check` → `tasks`/`full` → `core_calendar_get_calendar_upcoming_view`; объединить по датам, проверять статус каждой работы |
| «какие курсы / материалы» | `courses` → `core_course_get_contents`; инвентаризация всех модулей, файлов, страниц и уроков |
| «найди лекцию / презу / слайд» | course contents → тип модуля `page` или `lesson` → извлечь HTML/вложение/`iframe` → проверить Google Slides/PDF; подробности в §4 |
| «сделай/проверь задание» | `mod_assign_get_assignments` → `mod_assign_get_submission_status`, вложения, критерии, comments → составить или проверить результат; отправка только с явным разрешением |
| «оценки и замечания» | `gradereport_user_get_grade_items`, `gradereport_user_get_grades_table`, feedback из `mod_assign_get_submission_status` |
| «тесты» | `mod_quiz_get_quizzes_by_courses`, `mod_quiz_get_user_attempts`, `mod_quiz_get_quiz_access_information`; анализировать **только существующие** попытки, если доступно; не начинать тест автоматически |
| «уведомления, сообщения» | `message_popup_get_popup_notifications`, `core_message_get_unread_notification_count`, `core_message_get_conversations`; не отмечать прочитанными |
| «форум» | `mod_forum_get_forums_by_courses`, `mod_forum_get_forum_discussions`, при необходимости `mod_forum_get_discussion_posts` |
| «календарь» | `core_calendar_get_calendar_upcoming_view`, `core_calendar_get_action_events_by_timesort` |
| «что выполнено» | `mod_assign_get_submission_status` + `core_completion_get_activities_completion_status` + оценки; не приравнивать пустую отметку к невыполнению |
| «найди документ» | перебор доступных enrolled-курсов, разделов, `contents` и HTML-страниц; глобальный индекс поиска может быть отключён |

Общий подход: название курса → `id` курса → раздел → `id` **course module** (`cmid`) → `id` **instance** (`lessonid`, `assignid`, `quizid` и т.п.). Это *разные идентификаторы*. Для экземпляра урока `id` получай через `mod_lesson_get_lessons_by_courses`, для элемента курса — через `core_course_get_contents`/`core_course_get_course_module`.

## 4. Как действительно открывать лекции и презентации

### 4.1 Страница (`modname=page`)

1. Получить разделы через `core_course_get_contents` и `cmid` нужной страницы.
2. Вызвать `mod_page_get_pages_by_courses` с `{'courseids[0]': course_id}`; найти запись по `coursemodule == cmid`.
3. Проверить `content`: текст, HTML `<a href>`, `<iframe src>`, изображения, встроенные PDF и вложения `contents` из структуры курса.
4. Для Google Slides извлечь **фактический** `src` из `iframe` (HTML-entities `&amp;` декодировать, сохраняя ID и адрес). Это самостоятельная опубликованная презентация, а не обязательно скачиваемый `.pptx`.

### 4.2 Интерактивный урок (`modname=lesson`)

**Подтверждено 23.10.2026 на курсе «Введение в специальность»**. Раньше `mod_lesson_get_pages` показывал только метаданные страницы, а `mod_lesson_get_page_data` отвечал `cannotfindtimer`; это **не запрет на содержимое**, а отсутствие запущенной учебной попытки/таймера. Правильный маршрут:

1. `mod_lesson_get_lessons_by_courses` с `{'courseids[0]': course_id}` → найти `lesson.id` и `coursemodule`.
2. **Только чтение:** `mod_lesson_get_lesson`, `mod_lesson_get_lesson_access_information`, `mod_lesson_get_pages`, `mod_lesson_get_user_timers` → проверить `practice`, `grade`, `maxattempts`, `retake`, `timelimit`, `preventaccessreasons`, имеющиеся попытки и ID первой страницы. Обязательно понимать последствия перед открытием попытки.
3. Сначала пробовать `mod_lesson_get_page_data` с `{'lessonid': lesson_id, 'pageid': page_id}` (при активной попытке может работать сразу).
4. Если получена `cannotfindtimer`, вызов `mod_lesson_launch_attempt` с `{'lessonid': lesson_id}` **считается записью/началом или возобновлением попытки**, а не read-only. Разрешён при прямом запросе пользователя открыть/просмотреть этот урок **и** после проверки, что риск оценивания/расходования попыток отсутствует или пользователю понятен. Для потенциально оцениваемой, ограниченной попытками, неизвестной или чувствительной лекции сначала получить отдельное согласие; не запускать автоматически при поиске курса. Нельзя обходить ограничения доступа.
5. Повторить `mod_lesson_get_page_data`, читать `response['page']['title']` и **`response['page']['contents']`** (не верхнеуровневый `pagecontent`); в найденном HTML искать `iframe src`.
6. Не вызывать `mod_lesson_process_page`, `mod_lesson_finish_attempt` или `mod_lesson_view_lesson` без соответствующего запроса: они могут записывать ответы, завершать попытку, изменять завершённость модуля. Не сообщать, что просмотр *ничего* не изменил: открытие попытки может фиксироваться Moodle.

Проверенный **пример** (не жёстко привязываться к этим ID в будущих семестрах): курс `3417` («Введение в специальность. Осень 2026»), лекция №3 `cmid=137044`, `lessonid=5338`, `pageid=25554`. После запуска тренировочной попытки `get_page_data` вернул страницу «Презентация», в `page.contents` обнаружился опубликованный Google Slides `pubembed`. Аналогично найдены лекции №2 и №4. Эти факты проверены для данного курса, но не доказывают такой же формат остальных курсов.

### 4.3 Просмотр **самих слайдов**, а не только ссылки

- Сначала открывать найденный URL (обычно `https://docs.google.com/presentation/d/e/.../pubembed` или `/presentation/d/.../embed`) без Moodle-токена, убедиться в корректном документе по заголовку/метаданным и визуальному содержимому.
- Для опубликованного Google Slides доступен HTML просмотрщика; его можно получить через `Remote_Desktop_Commander.read_file(path=<URL>, isUrl=true)` или браузер. На лекции №3 проверено получение HTML с заголовком файла `.pptx` и текстом элементов слайдов. Сам по себе HTML объёмом в мегабайты НЕ означает, что разобраны все слайды: извлекать текст и номера страниц, сверять с видимым слайдом.
- Если формат/права позволяют, проверить публикационный PDF-экспорт либо прямой файл; **не предполагать**, что `pubembed` обязательно даёт доступ к PPTX/PDF. Для PDF или PPTX читать реальные страницы/слайды соответствующими инструментами, извлекать текст и, если важна графика, просматривать изображения страниц.
- Для поиска фразы по слайдам нормализовать пробелы, HTML-entities и Unicode; учитывать, что часть текста может быть картинкой и потребует визуальной проверки. Выводить точную ссылку и номер слайда **только если подтверждён**.
- Если парсинг текстового HTML не покрывает все слайды, использовать просмотрщик/скриншоты (при наличии доступа), не объявлять «в презентации нет» на основании неполного поиска.

**Подтверждено локальными вызовами 23.10.2026:** `mod_resource_get_resources_by_courses`, `mod_folder_get_folders_by_courses`, `mod_book_get_books_by_courses` (запросы успешно возвращали списки, хотя в исследованном курсе они пустые); `mod_page_get_pages_by_courses` (14 страниц), `mod_lesson_get_lessons_by_courses` (3 урока), `core_course_get_course_module`, `core_calendar_get_calendar_upcoming_view`, `core_completion_get_activities_completion_status`, `gradereport_user_get_grades_table`, `mod_quiz_get_quizzes_by_courses`. `core_course_search_courses` вызвался успешно, но по точному названию курса вернул 0 — использовать локальную фильтрацию enrolled-курсов как запасной вариант. `core_search_get_search_areas_list` на текущем сайте ответил `globalsearchdisabled`: не обещать полноценный глобальный поиск. `site_info` в октябре 2026 объявлял 464 метода — список **возможностей сервиса**, не доказательство студенческого доступа ко всем методам.

**Ранее подтверждено:** получение курсов, заданий, отправок, отзывов, оценок, уведомлений, календаря, тестов и существующих попыток, форумов, PDF/DOCX; загрузка *тестового файла* в личный черновик `user/draft`. Просмотр PPTX/XLSX и файлов из отдельных модулей зависит от типа ресурса и фактического доступа. Дополнительные безопасные методы и параметры — в `API_RECIPES.md`.

К внешним файлам Moodle (`webservice/pluginfile.php/...`) обращаться **с авторизацией только на точном домене `newlms.misis.ru`**, без перенаправления секретов третьим сторонам; сверять размер, MIME, магическую сигнатуру, количество страниц и возможность повторного чтения. Загруженный документ не означает, что он содержательно проверен. Ссылки на опубликованные Google Slides открывать отдельно и **без** Moodle-токена.

## 6. Политика действий и отчётность

- По умолчанию: **чтение** в рамках прав пользователя. Некоторые функции, чьё имя похоже на чтение (`view_*`), фиксируют просмотр и завершённость; перед вызовом проверять семантику метода, а не только название.
- **Требуется явная просьба пользователя**: запуск/продолжение оцениваемого теста или урока, ответы на вопросы, фиксация прохождения, отправка/изменение работы, запись в черновик, сообщение/форум, отметки «прочитано», подписки и любые изменения оценок. Для ограничения одной попыткой — особенно осторожно. Просьба «открой тренировочную лекцию» может разрешать именно её просмотр, но не ответы/завершение.
- Загрузка в `user/draft` ≠ прикрепление к заданию ≠ окончательная отправка. Каждое действие различать и подтверждать отдельно. Ни одной отправки ради тестирования.
- Не собирать материалы других студентов, скрытые задания и данные, на которые текущий пользователь не имеет права. Не обходить разграничение прав.
- `warnings` Moodle считать важными, но не всегда фатальными; `invalidparameter` — проверить структуру параметров; `cannotfindtimer` — проверить активность урока; `globalsearchdisabled` — переключиться на перебор видимых курсов; ошибка доступа — остановиться, а не обходить.
- **Отделять**: «нашёл ссылку» / «смог открыть файл» / «прочитал конкретный слайд» / «проверил содержание». Указывать, что известно, что не удалось проверить, и нужна ли помощь пользователя.
- Не менять локальные клиент, авторизацию, Windows, курс и пользовательские файлы при простой задаче чтения. Любые технические доработки — с бэкапом, без побочных эффектов и с регрессией.

## 7. Проверочный минимум после изменения навыка

1. `moodle_client.py check` возвращает `ok:true`; URL и пути актуальны.
2. `courses` находит «Введение в специальность»; `core_course_get_contents` выдаёт `page/lesson`.
3. `mod_page_get_pages_by_courses` с **`courseids[0]`** читает HTML и ссылки; `mod_lesson_get_pages` возвращает метаданные; **не запускать новый урок просто для теста**.
4. На уже открытом безопасном уроке `mod_lesson_get_page_data` выдаёт `page.contents` с `iframe`; проверить валидность опубликованной ссылки без токена.
5. Проверить чтение календаря и статусов работ; убедиться, что никакие тесты/задания/ответы не были отправлены.

## 8. Browser enrichment v11 — 25.10.2026

Moodle API-токен работает и защищён Windows DPAPI. Браузерная сессия Chrome
это отдельная авторизация, не считать её успешно сохранённой только по факту
входа. Требуется реальный `browser-status` -> authorized:true после закрытия
первого окна браузера.

- `moodle_client.py browser-cache-status` — статус локального DPAPI-кэша.
- `moodle_client.py browser-index --url URL` — чтение одной разрешённой
  студенту страницы page/book/glossary/folder. Сверить актуальные ACL,
  enrolled course, тип, URL, CMID. Quiz/Lesson в auto-index НЕ открывать.
- `moodle_client.py browser-find --query "тема"` — поиск по зашифрованному
  browser-кэшу с повторной проверкой прав. Кэш пуст -> пустой результат.
- `moodle_client.py hybrid-search --query "тема" --limit 5` — объединённый
  поиск с browser_matches; Chrome автоматически НЕ запускается.
- `--no-browser-cache` — исключить browser-кэш из поиска.
- `MISIS-Moodle-Web-Login.cmd` или `moodle_browser.py login` — новый видимый
  пользовательский вход, после перехода на /my/ автоматически подтверждает
  доступ и защищённо сохраняет cookies текущего изолированного Moodle-профиля.
  Скрытая консоль/Enter в новой версии не нужны.

  завершать пользовательские процессы без необходимости. Не читать пароль

## 9. Multimodal index v12 — 25.10.2026

Local parser for PDF/PPTX/images/video frames added to Moodle Bridge.
No paid APIs or external OCR uploads. Structure: PPTX tables/OOXML chart caches;
PDF text/tables/bitmap metadata/vector paths; optional local OCR on images;
video sampling with FFmpeg + optional OCR. Text and verified chart values only.
Raster chart data and image meaning are **not** inferred without a local VLM.

Commands:
- multimodal-index --cmid N [--max-file-mb 12] [--ocr]
- multimodal-status; multimodal-search --query TEXT
- video-frames-index --cmid N [--interval 20] [--max-frames 5] [--ocr]
- video-frames-status; video-frames-search --query TEXT
- hybrid-search --query TEXT --limit N includes optional new sources;
  --no-multimodal to omit both. Never starts Lesson/Quiz or submissions.

Real trial: PPTX cmid 136820 -> 54 slides, 9 tables and 20 images;
PDF cmid 133073 -> one page, 25 images and 814 OCR characters;
Yandex video cmid 148083 -> 3 frames, no OCR words. 116/116 tests PASS.
Files in encrypted DPAPI caches are not included in any source archive.
