# MISIS Moodle Bridge v11 — browser enrichment / приёмка
Дата: 25 октября 2026 года.

## Назначение и текущая готовность
Ядро моста: работоспособно на домашнем Windows ПК.
Новая функция v11: чтение учебных веб-страниц, которые открываются студенту
в браузере, в **отдельный зашифрованный локальный текстовый индекс**,
доступный из единого поискового интерфейса.

Браузерная авторизация на реальной сессии **не принята**:
в текущем старом Chrome видно «Личный кабинет | LMS MISIS»,
но отдельный защищённый файл `.moodle_browser_session.dpapi` отсутствует.
Новая версия auto-save прошла имитационные тесты, но должен пройти
реальный сценарий вход -> DPAPI сохранение -> завершение браузера ->
повторное открытие -> чтение страницы. Без него нельзя утверждать,
что Moodle Bridge полностью завершён.

## Новое в v11
- `moodle_browser_index.py` проверяет точное совпадение URL, типа, CMID
  и текущей видимости модуля через Moodle API перед каждым открытием.
- Автоматически НЕ обходит все курсы, не открывает Lesson/Quiz,
  не начинает учебные попытки, не читает произвольные сайты.
- Разрешены только индивидуально указанные страницы типа Moodle
  `page`, `book`, `glossary`, `folder`, строго на
  `https://newlms.misis.ru` с одним параметром `id`.
- `browser-index --url URL` читает открытую для студента страницу
  и сохраняет видимый текст без cookie, пароля и API-токена
  в `.moodle_browser_content.dpapi` (Windows CurrentUser DPAPI).
  Если браузер ещё не авторизован, возвращает `needs_browser_login`
  и ничего не сохраняет.
- `browser-cache-status` показывает только количество локальных страниц.
- `browser-find --query "тема"` ищет по кэшу, перед выдачей результатов
  заново проверяя видимость модулей в Moodle. Снятая с публикации
  страница автоматически исчезает из результатов поиска.
- `hybrid-search` включает `browser_matches` из этого кэша
  по умолчанию; `--no-browser-cache` отключает кэш.
  Поиск НЕ запускает Chrome сам по себе.

## Команды
Исполняются на домашнем ПК из `C:\Users\user\Documents\MISIS-Moodle-Bridge`.

- `python moodle_client.py check`
- `python moodle_client.py hybrid-search --query "лекция" --limit 5`
- `python moodle_client.py browser-cache-status`
- `python moodle_client.py browser-index --url "https://newlms.misis.ru/mod/page/view.php?id=123456"`
  (число 123456 — синтетический пример, подставить реальный видимый URL).
- `python moodle_client.py browser-find --query "лекция" --limit 5`
- `python moodle_client.py browser-status`
- `MISIS-Moodle-Web-Login.cmd` — запуск нового видимого браузера входа.

## Ограничения
- В старом Chrome на ПК сейчас открыта авторизованная сессия.
  До закрытия прежнего интерактивного запуска и перепроверки
  **не следует запускать второй Chrome с тем же профилем**.
- Два компонента разделены: API-токен DPAPI работает независимо,
  а браузерная сессия **пока не сохранена подтверждённым образом**.
- 79 страниц Lesson требуют учебной попытки. Их нельзя объявлять
  доступными только благодаря появлению веб-браузера.
- Семь Google Slides ссылок возвращают HTTP 410;
  некорректные/удалённые исходники не исправляются парсером.
- Не читать/копировать секреты из Chrome или из DPAPI вручную.

## Browser-status fast-fail (v11.1)
- Если защищённая сессия ещё не сохранена, browser-status отвечает authorized:false, reason:protected_session_missing **без запуска второго Chrome**.
- browser-read в этом состоянии отвечает needs_browser_login, не трогая текущий авторизованный браузер.
- Реальный запуск обоих сценариев проверен на домашнем ПК; 104/104 автоматических теста пройдены.
