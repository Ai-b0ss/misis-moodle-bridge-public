# MISIS Moodle Bridge — v10: приёмочные результаты, 25.10.2026

## Вердикт
**Ядро системы работает; браузерный режим не принят как завершённый.**
Проверены операции read-only Moodle API, индексация и объединённый поиск.
Пользователь подтвердил успешный ручной вход в отдельный браузер Moodle;
окно «Личный кабинет | LMS MISIS» наблюдалось в Windows.
При этом процесс старой версии входа ожидал Enter в недоступной пользователю консоли,
а защищённый файл `.moodle_browser_session.dpapi` при последней проверке отсутствовал.
Следовательно, у v10 **ещё нет подтверждённого успешного end-to-end сохранения
реальной авторизованной сессии**, и нельзя заявлять, что повторный браузерный вход работает.

## Изменения v10
1. Исправлено Unicode-кодирование JSON результата PP-OCRv5 и OLE PowerPoint worker
   для Windows с кодовой страницей CP1251: ASCII-safe JSON; кириллица больше
   не превращается в символы замены при декодировании UTF-8.
2. Исправлен тест старых PPT для надежной проверки в UTF-8/CP1251.
3. Убран обязательный ручной Enter из **новых** запусков `moodle_browser.py login`.
   Программа должна автоматически дождаться перехода студента на `/my/`,
   проверить страницу в отдельной вкладке и сохранить cookies только домена Moodle.
4. Файл сессионных cookies отдельного Chrome-профиля защищён локально
   Windows CurrentUser DPAPI. Пароль не копируется и не сохраняется.
5. Добавлены тесты на шифрование cookie, проверку домена, автообнаружение
   успешного входа без консоли.
6. Тестовый прогон на реальном Windows-компьютере: **99/99 PASS**.
   Эти тесты включают симулированный успешный браузерный вход, но
   не заменяют проверку реальной сессии после завершения процесса.

`python moodle_client.py check`
`python moodle_client.py overview`
`python moodle_client.py deadlines`
`python moodle_client.py hybrid-search --query "тема" --limit 20`
`python moodle_client.py browser-login`
`python moodle_client.py browser-status`
`python moodle_client.py browser-read --url "https://newlms.misis.ru/my/"`

`MISIS-Moodle-Web-Login.cmd` — альтернативный запуск интерактивного входа:
в новой версии **не должен требовать консольного Enter**.

## Что не принято
- Реальное сохранение и восстановление браузерной сессии после ручного входа.
- Чтение конкретных закрытых для Moodle API, но доступных студенту в браузере страниц.
- Возможность читать все 79 Lesson без создания попыток: не подтверждена,
  поскольку ограничения задаёт сам Moodle.
- Полное покрытие удалённых презентаций и большого видео.
- Исправление 45 предупреждений No access rights (соответствуют ACL сервера).
- Нет постоянно работающего независимого облачного сервера:
  удалённые команды требуют доступного домашнего Windows ПК.

## Безопасность сборки
`release-v10-source` и соответствующий ZIP содержат **исходный код,
тесты и документацию**, но не содержат учетные данные, DPAPI базы,
браузерные профили, текстовые индексы, персональные учебные отчёты
или бинарные материалы. Ни одна попытка теста не запускалась и оценки не менялись.

## Следующая реальная проверка
После завершения старого интерактивного процесса нужно **один раз** войти
через новый auto-save launcher и дождаться автоматического завершения.
Далее, когда Chrome закрылся, проверить `browser-status`
и `browser-read` на отдельной странице Moodle. До этих операций
нельзя считать браузерную часть готовой.

- В \`moodle_hybrid.py\` JSON CLI переведён на ASCII-safe сериализацию.
- Повторный реальный запуск завершился с кодом 0: 3 совпадения Moodle, 3 вложения, 3 слайда, 3 результата Drive, 3 Яндекс.Диск.
